# 第一版模型自主性与 Agent 边界候选

记录时间：2026-07-20T00:34:54+08:00

## 决策依据

课程 Project B 不要求应用必须包含 agent。课程原文把 agent 定义为同时具备“自主多轮决策、自主调用工具、根据反馈自我修正”的部分；如果包含，就必须自行编码主循环、工具分发和治理护栏，并在移除真实 LLM 后仍可用 mock/stub 做确定性单元测试。单轮或受应用流程调用的生成、问答、摘要属于普通 AI 功能。

当前产品已经有明确的确定性权威边界：材料外发由策略/同意控制，知识覆盖由用户确认，轨迹题由 oracle 判定，掌握状态与计划由版本化规则推导。问题是要不要在第一版额外加入一个能自主选择工具并循环修正的部分，而不是“要不要使用模型”。三个方案都可以使用模型做候选知识映射、适配解释、练习生成和期末资料分析。

## 方案比较

| 维度 | 1. 受约束 AI 功能，无 agent | 2. 有界学习规划 agent | 3. 全流程学习教练 agent |
| --- | --- | --- | --- |
| 自主循环 | 无；应用状态机逐步调用模型 | 有；只在规划任务内循环 | 有；诊断、教学、练习、规划均可循环 |
| 工具自主选择 | 无 | 只读状态/来源工具 + 提交候选计划 | 范围广，可能包含材料、教学和计划工具 |
| 权威写入 | 确定性规则 + 用户确认 | agent 只提案；验证器/用户确认后写入 | 需要大量细粒度审批与回滚 |
| 产品价值 | 可解释、稳定地完成已确认主流程 | 展示自主搜集证据、修正规划的 agent 能力 | 体验最灵活，但很容易范围失控 |
| 确定性测试负担 | 中；schema、规则、状态机和 provider mock | 高；循环、工具顺序、反馈修正、预算与护栏 | 很高；状态空间和安全面明显扩大 |
| 第一版风险 | 可能不够“agentic”，但不影响 Project B 合规 | 需要证明 agent 比普通函数编排有真实价值 | 容易削弱材料保真、学习测量和分发完成度 |

## 方案 1：受约束 AI 功能，无课程定义的 agent（推荐）

模型通过具名端口被应用调用：

- `propose_concept_coverage`：返回结构化候选映射，等待用户确认；
- `generate_explanation`：根据已确认来源和学习证据生成适配解释；
- `generate_practice_candidate`：生成受 rubric/oracle 约束的练习候选；
- `analyze_exam_material`：返回往年卷题型、覆盖和难度候选，不训练模型；
- `generate_feedback`：解释确定性/rubric 结果，不能给自己提权。

应用状态机决定何时调用哪个端口；每次调用有固定 schema、来源范围、预算、超时和可重试语义。模型失败只让当前候选/解释进入可恢复状态，不改变权威知识、计划、授权或掌握状态。

该方案仍是有真实 AI 能力的应用，只是不把普通模型调用误称为 agent。工程深度来自增量材料、来源保真、学习证据、双模式计划、安全凭据、WebUI、测试和分发，而不是自主循环数量。

## 方案 2：有界学习规划 agent

只在用户明确发起“重新规划”或进入期末周模式后运行一个 `StudyPlannerAgent`。它可以自主决定调用哪些只读工具来补齐规划上下文，并依据确定性验证器的反馈修正一次候选计划：

```text
goal received
  -> choose/read allowed course-state tools
  -> propose plan revision
  -> deterministic policy/constraint validation
  -> if rejected and budget remains, revise
  -> present proposal and evidence to user
  -> user confirms -> application commits PlanRevision
```

候选工具：

- `get_confirmed_coverage`
- `get_learning_evidence_summary`
- `get_existing_future_tasks`
- `get_confirmed_study_focus`
- `get_exam_goal`
- `validate_plan_proposal`
- `submit_plan_proposal`

护栏：最多固定轮数/工具次数/token/时间；工具参数使用 schema；不提供读取任意文件、扩大外发、管理凭据、删除数据、直接写掌握状态或直接激活计划的工具；所有提案引用输入 ID 和原因；用户确认仍是权威写入门禁。

最小 mock 测试必须覆盖：缺少证据时自主补查、无效计划被验证器拒绝后修正、预算耗尽、重复工具调用、注入材料、工具异常、越权工具、确定性重放和最终提案未确认时零写入。

## 方案 3：全流程学习教练 agent

agent 自主决定诊断轮次、选择解释方式、生成/调用练习工具、判断是否继续追问并重排计划。它更接近自由对话教练，但会把 M1-M3 的多数控制权放入同一循环，必须额外处理会话恢复、工具幂等、长循环、错误归因、并发计划修改、材料注入、费用预算和每种写操作的审批/回滚。

这个方案与当前“来源可追溯、用户确认知识、确定性学习证据”方向存在更高张力。除非自主教练本身是学生最想展示的核心创新，否则不建议放入第一版。

## 三种方案共同不变量

1. 模型不能扩大材料外发、读取未选文件、查看凭据、绕过用户确认或把输出写成课件事实。
2. 轨迹题等可判定任务由确定性 oracle 负责正确性；模型不能为自己的答案评分后写入掌握状态。
3. `CoverageDecision`、`StudyFocus` 确认、`PlanRevision` 激活和 `ConsentRecord` 都由应用域规则/用户动作完成。
4. provider 适配器可被 mock；无真实 LLM 时核心状态机、安全规则、计划版本和学习证据测试仍运行。
5. 所有模型调用有来源范围、schema、超时、预算、取消、幂等键、错误脱敏和最小化审计。
6. 无论是否叫 agent，都不能宣传“能自主完成学习”或替学生完成考核。

## 推荐

推荐第一版采用方案 1。原因不是 agent 难做，而是当前真实价值已集中在“增量课件 -> 确认知识 -> 计划 -> 引导学习 -> 期末重排”，其中用户确认和确定性证据是核心护栏；把工具选择放进循环暂时没有消除明显的用户负担，反而会扩大测试和安全范围。

若学生希望项目必须展示 agent 能力，方案 2 是可控的折中：只让 agent 生成可审查的计划提案，不授予权威写入。方案 3 延期。

## 选择后的规约影响

- 选择方案 1：在 SPEC 明确“含 AI 功能但不含课程定义的 agent”，固定模型端口和 schema；PLAN 不创建 agent 主循环 task。
- 选择方案 2：SPEC 增加 agent 目标、状态机、工具合同、治理护栏和 mock 验收；PLAN 单独拆分循环、工具分发、验证器、预算、恢复与安全测试。
- 选择方案 3：需要重新评估 M1-M3 边界、第一版范围和可验收性，不能直接沿用当前候选 SPEC 进入计划。
