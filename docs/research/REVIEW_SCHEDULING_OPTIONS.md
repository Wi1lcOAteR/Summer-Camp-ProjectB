# 复习目标时间与双模式调度语义

记录时间：2026-07-20

## 状态与目的

D-012 已于 2026-07-20 确认：学期中使用持续安排；考试日期通常稍后给定，用户录入日期后可以显式进入期末周模式。本文保留三种候选的比较证据，并固定已选双模式的时间/证据/测试合同；它仍不选择 BKT、FSRS、固定间隔表或其他具体调度算法。

学习科学基线只支持有限结论：主动提取和分散练习通常有价值，合适间隔会随目标保持时长变化；它不支持把某一套间隔当作所有课程和学生的普适真理。

## 三种方案比较

| 维度 | 可选目标日期 + 自适应 | 仅长期掌握 | 手动日期为主 |
| --- | --- | --- | --- |
| `Course.target` | 可选；存在时参与优先级 | 不存在 | 可选，仅显示/提醒 |
| 自动生成到期时间 | 是 | 是 | 否或仅提供建议 |
| 无考试日期时 | 退化为长期保持 | 原生行为 | 依赖学生手工添加 |
| 临近期末取舍 | 可结合剩余时间与薄弱证据 | 没有截止时间信号 | 由学生自己排序 |
| 学生管理负担 | 中 | 低 | 高 |
| 规则与测试复杂度 | 中至高 | 中 | 低至中 |
| “为什么现在复习” | 证据 + 间隔 + 目标剩余时间 | 证据 + 间隔 | 学生设置 + 可选建议 |
| 主要风险 | 算法产生虚假最优感或冲刺过载 | 与真实考试节奏脱节 | 退化为普通待办/提醒器 |

## 已采用：可选考试日期 + 双模式安排

### 已确认状态

```text
continuous
  -> exam_date_set -> finals_available
  -> explicit_enter -> finals

finals
  -> exam_date_changed -> revise future tasks
  -> explicit_exit/date_cleared -> continuous
  -> exam_reached -> unresolved post-exam transition
```

课程可以没有考试日期，且默认持续安排。录入日期只使期末模式可用，不自动切换；用户显式进入后，调度输入才增加剩余可用天数、知识依赖、薄弱证据、老师重点、往年卷映射与已存在任务。不能把目标日期写成“每天任务越多越好”。学生修改/清除日期或退出期末模式时，只重算未开始的未来任务，历史 `Attempt` 和 `LearningEvidence` 不变。

### 仍需学生后续确认的参数

- 目标表示考试的本地日期，还是精确时间；
- 是否记录每天可投入量、不可用日期或最后冲刺上限；
- 目标到期后是归档课程、转长期保持，还是询问新目标；
- 自动重排是否需要逐次确认。

这些参数不改变 D-012 已确认的“持续模式为默认、日期 + 显式操作才进入期末模式”。

### 期末资料与计划输入

往年卷和老师重点作为用户显式导入的材料角色，先映射到用户已确认的课程知识，再参与排序。第一版的“拟合”仅表示结构、题型、知识点与难度分析，以及同类练习选择/生成；不触发模型训练或微调，不预测原题，也不扩大材料外发范围。完整增量流程见 `docs/research/INCREMENTAL_COURSE_WORKFLOW.md`。

## 方案 2：仅长期掌握

### 候选状态

```text
evidence appended
  -> derive review need
  -> choose next retrieval window
  -> review attempt
  -> reschedule from result
```

调度只依赖证据、知识依赖和既有间隔，不收集考试日期。它更容易保持产品承诺克制，但学生临近考试时无法表达“有限时间内优先修补哪些知识点”，只能手工修改优先级或接受长期顺序。

## 方案 3：手动日期为主

学生创建/修改每个复习任务的时间；系统保留来源、证据和完成结果，可以给建议但不自动覆盖。它降低算法风险，却把持续计划工作转回学生，M3 的独特价值可能只剩一个带证据的待办列表。

## 三种方案共同的不变量

1. 复习任务先要求主动提取，再显示解释或原页；重读不能自动算完成。
2. 每个 `ReviewTask` 都显示到期原因、来源证据、策略版本与最近一次变更原因。
3. 修改目标/策略不删除或重写历史 `Attempt`、`LearningEvidence` 和旧任务版本。
4. 没有足够证据时可以安排“诊断任务”，但不能冒充已知遗忘曲线。
5. 学生可以完成、跳过、延后或取消任务；系统记录动作，不用惩罚性文案推断动机。
6. provider/LLM 可以生成题面、解释或候选映射，但不能直接决定权威 `due_at`、优先级、知识覆盖或掌握状态。
7. 时间规则必须可用虚拟时钟确定性运行；测试不等待真实秒、天或考试日期。
8. 离线一段时间后重新打开应用，调度一次性对账，不能为每个错过时间点重复创建任务。
9. 新材料只在知识覆盖经用户确认后进入未来计划；重排必须生成 `PlanRevision`，不能抹去旧计划。
10. 考试日期和材料角色都不构成外发授权；往年卷/老师重点沿用相同的显式同意与最小化规则。

## 候选数据合同

### `CourseReviewGoal`

| 字段 | 语义 |
| --- | --- |
| `course_id` | 本地课程身份 |
| `mode` | 已确认的 `continuous` 或 `finals` |
| `target_local_date` | 可选考试日；是进入 `finals` 的必要非充分条件，不是隐含 UTC 午夜 |
| `timezone_id` | IANA 时区 ID，例如 `Asia/Shanghai`；不只存当前偏移量 |
| `version` | 每次修改递增，用于解释重排 |
| `changed_at` | UTC instant |
| `change_reason` | 学生设置/清除日期、显式进入/退出期末模式等白名单原因 |
| `finals_entered_at` | 可空；显式进入期末模式的 UTC instant |

### `ReviewPolicy`

| 字段 | 语义 |
| --- | --- |
| `policy_id`, `version` | 可重放的规则身份 |
| `mode` | 对应目标语义 |
| `parameters` | 经过范围校验的显式参数；不能藏在 prompt |
| `effective_from` | UTC instant；历史证据仍引用旧版本 |

### `ReviewTask`

| 字段 | 语义 |
| --- | --- |
| `id`, `concept_id` | 任务与知识点 |
| `not_before` | 最早可开始的 UTC instant，可为空 |
| `due_at` | 计算/手动到期的 UTC instant |
| `display_timezone_id` | 用户看到日期时使用的时区 |
| `reason_code` | 机器可测试的原因类别 |
| `reason_inputs` | 证据 ID、前次结果、目标版本等白名单输入，不存作答正文 |
| `policy_version` | 产生该任务的规则版本 |
| `priority` | 有界、可解释的排序值；不等于掌握真值 |
| `status` | 当前任务状态 |
| `supersedes_task_id` | 重排时链接旧任务，不覆盖历史 |

## 任务状态机

```text
scheduled -> due -> in_progress -> completed
          -> snoozed -> scheduled
          -> skipped
          -> cancelled
scheduled/due -> superseded
```

- `completed` 必须关联实际 `Attempt`；
- `snoozed` 记录学生选择的新时间与原因，不伪造学习证据；
- `skipped` 不自动降低掌握状态，只作为后续调度输入；
- `superseded` 保留旧任务及其生成理由，指向新任务；
- 对同一概念、同一策略版本和同一证据集合的重算必须幂等。

## 到期原因合同

界面文案可以变化，但必须由稳定 `reason_code` 和白名单输入生成：

| reason_code | 最小输入 | 用户可见解释示例的语义 |
| --- | --- | --- |
| `initial_gap` | 诊断证据 | 起点检查暴露了具体薄弱项 |
| `post_explanation_check` | 同构/迁移证据 | 刚完成理解检查，需要后续主动提取 |
| `prior_review_result` | 上次 Attempt | 根据上次变式表现重排 |
| `prerequisite_due` | 依赖概念 | 先巩固后续知识依赖 |
| `target_pressure` | 目标版本、剩余时间 | 目标日期临近且仍缺必要证据（仅方案 1） |
| `new_material` | 批次、覆盖决定、计划版本 | 新确认知识改变了未来安排 |
| `teacher_focus` | 用户确认的重点映射 | 老师明确重点参与了期末排序 |
| `past_paper_pattern` | 用户确认的往年卷映射 | 往年卷中重复题型/知识覆盖参与排序 |
| `manual_choice` | 学生操作 | 学生手动指定或延后（方案 3/共同覆盖） |

不能使用“AI 觉得你忘了”作为唯一解释。

## 时间与时区语义

### 存储

- 事件时间存 UTC instant；
- 用户日历目标存 local date + IANA timezone，不能先转成隐含 UTC 午夜再丢失原意；
- 显示时使用任务记录的时区和当前用户时区策略；
- 时长/超时使用单调时钟，不使用可回拨的墙上时间。

### 夏令时与时区变化

- 某些时区存在不存在或重复的本地时间；若未来允许选择精确提醒时间，必须定义前移/后移规则并显示结果；
- 用户改变时区时，考试 local date 通常保持日历语义，已生成任务是保持 instant 还是保持本地时间需由策略明确；
- 第一版若只按日期显示，可减少 DST 歧义，但仍要把“今日”从注入时钟和 `timezone_id` 计算。

## 确定性测试矩阵

| 场景 | 固定输入 | 必须验证 |
| --- | --- | --- |
| 同一时刻重算 | Clock、证据、策略版本相同 | 任务集合与 ID/幂等键不重复 |
| 新增失败证据 | t0 后追加 Attempt | 新任务引用新证据，旧任务保留或被 supersede |
| 完成复习 | due task + Attempt | 追加证据并生成至多一个后续任务 |
| 跳过/延后 | 学生动作 + 新时间 | 不生成正确作答证据；原因可见 |
| 离线后恢复 | Clock 从 t0 跳到 t1 | 一次对账，无任务风暴或逐 tick 补建 |
| 录入日期但未进入期末模式 | goal 有日期、mode 为 `continuous` | 不产生 `target_pressure`，模式不改变 |
| 显式进入期末模式 | 日期有效、用户动作、确认覆盖 | mode 变为 `finals`，只重排未来任务 |
| 修改目标日期 | goal v1 -> v2 | 只重排未来未开始任务，历史 attempt 不变 |
| 清除目标日期 | finals/continuous -> continuous | 不丢任务历史，后续不再产生 `target_pressure` |
| 目标已过去 | Clock > target | 不创建过去无限任务；进入明确终态/询问流程 |
| 跨午夜 | 同一 instant，不同时区 | “今日/逾期”由指定时区一致计算 |
| DST 跳变 | 有 DST 的测试时区 | 不产生不存在本地时间或重复任务 |
| provider 失败 | 固定调度输入，provider mock error | `due_at`/priority 不变，反馈任务可重试 |
| 策略升级 | policy v1 -> v2 | 新任务引用 v2，旧任务仍可按 v1 重放 |

测试使用 `FakeClock`/`Clock` port 和固定 IANA tzdata 版本；断言 domain instant/reason，而不是依赖本机格式化字符串。

## 不在 D-012 中决定的内容

- 具体间隔公式、阈值、优先级权重；
- 每日任务上限与可用时间；
- 系统通知、日历同步、邮件或移动推送；
- 是否使用 FSRS/BKT 或模型生成调度建议；
- UI 的日历/列表具体布局；
- 考试日期是否属于敏感数据的保留期限（安全基线已要求最小化）。

## D-012 确认结果

1. `CourseReviewGoal.mode` 固定为默认 `continuous` 与显式 `finals`；考试日期可选，且只是进入期末模式的必要非充分条件。
2. 目标创建、修改、清除、显式模式切换与历史保留状态流写入 M3。
3. `new_material`、`teacher_focus`、`past_paper_pattern` 与 `target_pressure` 作为可解释候选原因；具体权重未选择。
4. 第一版必须覆盖测试矩阵中的日期/模式分离、目标修改/清除、离线恢复和 provider 失败。
5. 后续单独确认调度算法/参数、期末启用窗口和资料格式，不把 D-012 授权扩大为这些选择。
