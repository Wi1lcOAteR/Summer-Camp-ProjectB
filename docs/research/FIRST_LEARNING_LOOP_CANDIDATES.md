# 首个“看懂 + 复习”学习闭环候选

记录时间：2026-07-19

## 状态与边界

本文为 D-011 提供可验收设计。学生表示没有具体偏好并授权从既有候选中选择，智能体采用已推荐的“互斥与竞态条件”作为第一版首个纵向切片。其余候选保留为后续扩展，不进入首个切片。

本文不复制课件正文、图片或原题。所有测试种子使用合成数据，正式内容只能在学生选择知识点后，通过本地 `SourceReference` 指向学生自己的课件页。

## 决策结果

- 首个知识点：并发中的互斥与竞态条件；
- 第一轮包含：共享状态、非原子读-改-写、线程交错、竞态条件、临界区，以及一种互斥修复的安全性理由；
- 第一轮排除：同步原语大全、高级内存模型、死锁证明、公平性算法和并发章节全量覆盖；
- 进程/调度与地址空间/地址转换保留为后续知识点，用于验证共同数据合同是否可扩展；
- D-011 的授权只覆盖知识点选择，不决定复习间隔、模型/provider、agent 或部署。

## 共同学习闭环

三个候选必须共用同一状态流，不能为每个知识点写一套聊天流程：

```text
选择学习目标
  -> 展示来源范围并取得处理策略
  -> 2-3 个低成本起点探针
  -> 按失败类型选择解释层级与原页
  -> 学生自我解释
  -> 一个同构检查 + 一个迁移检查
  -> 追加 LearningEvidence
  -> 推导带理由的 MasteryEstimate
  -> 创建后续 ReviewTask
  -> 后续先主动提取，再显示反馈
```

### 共同成功维度

| 维度 | 可观察证据 | 不能充当证据的行为 |
| --- | --- | --- |
| 术语边界 | 学生能区分相邻概念并给出必要条件 | 点击“看懂了”、阅读时长 |
| 因果模型 | 学生能预测状态变化并解释原因 | 复述模型原句 |
| 来源核对 | 学生能把结论对应到存在的课件页并指出冲突 | 模型声称“来自课件” |
| 迁移 | 学生能处理表面不同但结构相同的新情境 | 重做完全相同的题 |
| 保持 | 在后续会话先尝试主动提取并再次达到阈值 | 同一会话立即重复 |

## 候选 1：互斥与竞态条件

### 候选知识图

```text
并发执行
  -> 共享状态
  -> 非原子读-改-写
  -> 线程交错
  -> 竞态条件
  -> 临界区与互斥目标
  -> 修复方案的不变量、进展与公平性
```

第一轮不应同时覆盖全部同步原语、死锁证明和高级内存模型；否则知识点会从一个闭环膨胀为整章课程。

### 起点诊断候选

1. **概念区分**：给出两个包含共享变量的短场景，让学生判断“并发”是否必然意味着“竞态”，并说明必要条件。
2. **轨迹预测**：给出两条合成线程的读/改/写步骤，让学生列出一个可能终值或指出非确定性来源。
3. **反例定位**：给出一个看似保护了代码但仍存在窗口的合成方案，让学生标出最短错误交错。

诊断不是考试：每个探针只定位失败类型，不立即产生“未掌握”的永久标签。

### 适配解释分支

| 诊断信号 | 解释重点 | 理解检查 |
| --- | --- | --- |
| 把并发等同于竞态 | 共享状态、冲突访问和时间依赖三个必要条件 | 让学生构造“并发但无竞态”反例 |
| 不会展开读-改-写 | 把一条语句拆为可交错事件，并对照原页代码 | 对新表达式列出事件序列 |
| 能算终值但说不清原因 | 用状态表要求逐步说明 happens-before/交错关系 | 隐去一步，让学生补齐因果链 |
| 修复只看最终结果 | 区分互斥、安全性、进展与公平性 | 比较两个都“偶尔正确”的方案 |

### “看懂”候选标准

学生必须同时完成：

- 用自己的话说明竞态发生的条件及临界区目的；
- 对未见过的两线程合成轨迹给出一个合法执行并定位错误窗口；
- 对一个候选修复说明它保护了哪个不变量，以及仍可能有什么进展问题；
- 每项结论关联本地存在的课件页或明确标为系统补充；
- 在后续变式轨迹中再次完成，而不是只记住同一终值。

### 确定性测试种子

- 用事件数组表示 `read(x)`, `compute`, `write(x)`，枚举受限交错并计算合法终值集合；
- 用锁区间标记验证同一锁保护的临界段不会重叠；
- 对学生提交的事件顺序检查线程内顺序、事件完备性和目标终值；
- provider mock 只返回解释文案，不能决定轨迹正确性或掌握状态。

## 候选 2：进程与调度

### 候选知识图

```text
程序与进程
  -> 进程状态与上下文
  -> 就绪队列/运行/阻塞
  -> 调度策略
  -> 时间线
  -> 响应、等待、周转等指标
  -> 策略取舍
```

第一轮应选择少量策略和已明确的指标定义，避免不同教材对到达时间、抢占和并列规则的差异造成伪错误。

### 起点诊断候选

1. **状态模型**：给出 CPU、I/O 事件，要求预测进程状态变化并说明触发原因。
2. **调度时间线**：给出少量进程的到达/运行参数和一条明确策略，要求生成时间线。
3. **指标解释**：给出已生成时间线，让学生区分并计算两个指定指标。

### 适配解释分支

| 诊断信号 | 解释重点 | 理解检查 |
| --- | --- | --- |
| 混淆程序与进程 | 地址空间、执行状态和 OS 记录的区别 | 对同一程序的两个实例比较状态 |
| 状态转换靠背箭头 | 用事件而非图形位置解释转换 | 给新事件序列预测状态 |
| 会排时间线但指标错 | 固定指标定义，逐段累计而非套公式 | 对相同时间线计算另一进程 |
| 只追求单一“最好策略” | 明确负载与评价指标的取舍 | 改变到达模式后重新比较 |

### “看懂”候选标准

- 能解释至少一个进程状态转换的事件原因；
- 对参数化进程集合按指定策略生成合法时间线；
- 根据 SPEC 固定定义计算目标指标，并解释策略为何改变结果；
- 后续使用不同到达/运行参数仍能完成。

### 确定性测试种子

- 输入 `arrival`, `burst`, `priority` 和明确的抢占/并列规则，纯函数生成时间线；
- 从时间线独立计算指标，用双实现或不变量核对总运行时间；
- 使用虚拟时钟测试 ReviewTask，不依赖真实等待；
- 模型只能解释已计算结果，不能生成权威时间线。

## 候选 3：地址空间与地址转换

### 候选知识图

```text
进程隔离
  -> 虚拟地址与物理地址
  -> 地址组成/映射结构
  -> 权限与有效性
  -> 转换结果或异常
  -> 缓存/多级结构（后续扩展）
```

第一轮必须固定一种简化映射模型和位宽，不应同时覆盖分段、分页、多级页表、TLB、置换和换页全过程。

### 起点诊断候选

1. **概念区分**：让学生解释为什么两个进程可以使用相同虚拟地址而不指向相同状态。
2. **位域拆分**：给出参数化地址宽度和页大小，要求拆出页号与页内偏移。
3. **映射判断**：给出合成表项的有效/权限/映射字段，要求得到物理地址或异常类型。

### 适配解释分支

| 诊断信号 | 解释重点 | 理解检查 |
| --- | --- | --- |
| 把虚拟地址当物理地址别名 | 隔离、每进程映射与 OS/MMU 职责 | 比较两个进程的同值虚拟地址 |
| 位域拆分错误 | 从页大小推导偏移位数，不背固定数字 | 改变页大小重新拆分 |
| 只会查表不检查权限 | 按有效、权限、映射顺序判定 | 加入只读/无效表项变式 |
| 依赖课件结构图位置 | 把图转为明确输入/输出关系 | 用文本表重建转换步骤 |

### “看懂”候选标准

- 能说明虚拟地址空间解决的至少一个隔离问题；
- 根据给定参数正确拆分地址并完成映射或报告正确异常；
- 能解释结果依赖哪些表项状态和权限，而非只给数值；
- 后续改变位宽、页大小或表项后仍能完成。

### 确定性测试种子

- 用小位宽整数和合成表项实现纯函数映射 oracle；
- 分别生成有效、无效、只读写入和越界情形；
- 检查页内偏移保持不变等不变量；
- 图像/模型解析只提供候选来源，正确结果由参数化 oracle 判定。

## 稳定数据合同

无论选择哪个知识点，下列字段可保持一致：

| 对象 | 候选字段 | 约束 |
| --- | --- | --- |
| `ConceptSeed` | `concept_id`, `title`, `prerequisites`, `source_refs`, `version` | 每个概念至少有本地来源或标为系统补充 |
| `ProbeTemplate` | `probe_id`, `concept_ids`, `kind`, `parameters`, `oracle_ref`, `difficulty` | 模板与实例分离；参数可重放 |
| `Attempt` | `attempt_id`, `probe_instance`, `response_ref`, `started_at`, `submitted_at` | 不在普通日志存作答正文 |
| `RubricCriterion` | `criterion_id`, `description`, `evaluator_kind`, `weight`, `required` | 权重不能掩盖必需条件失败 |
| `LearningEvidence` | `concept_id`, `attempt_id`, `criterion_results`, `source_refs`, `outcome` | 追加式；评分依据可查看 |
| `ReviewVariant` | `template_id`, `seed`, `due_reason`, `prior_evidence_ids` | 能生成结构相同、表面不同的任务 |

## 评分与模型边界

1. **规则可判定结果**：轨迹、调度表、数值映射、合法状态转换由确定性 oracle 评分。
2. **解释性回答**：可由 rubric + 受限模型建议反馈，但模型结果不能直接写入最终掌握状态；需要结构化标准、来源和可撤销记录。
3. **部分正确**：分别记录概念、过程、结论和来源，不把单一总分隐藏失败类型。
4. **不知道/跳过**：是有效诊断信号，不应被自动补全成正确回答。
5. **学生纠正**：允许标记题意、来源或评分错误；纠正追加记录，不覆盖原证据。

## 候选掌握状态门禁

```text
unknown
  -> evidence_collected
  -> developing
  -> demonstrated_now
  -> retained
```

- `demonstrated_now` 至少需要一个同构检查和一个迁移检查满足必需 rubric；
- `retained` 只能由后续会话中的主动提取证据产生；
- 时间间隔与阈值尚未确认，测试使用可注入时钟，不把真实等待写进测试；
- 任一状态都显示证据和算法版本，不向用户宣称客观真值。
